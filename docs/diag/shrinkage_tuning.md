# Early-season shrinkage: why the prop board was a wall of unders

## The symptom

Week 2 of 2026. Every top prop edge on the board was an "under" at roughly
+0.50 edge, while the fantasy board projected Josh Allen at 30 points. Two
surfaces of the same app disagreeing about the same player.

## The two paths

The app projects the same quantity two different ways.

| | prop path | fantasy path |
|---|---|---|
| entry point | `evaluate_prop` | `build_fantasy_summary` |
| mean | raw GLM | `clip((1-w)*trailing + w*GLM)` then context factors then market anchor |
| market anchor | no | yes |

For Josh Allen, 2026 week 2, before the fix:

| stat | prop path | fantasy path | Kalshi line |
|---|---|---|---|
| passing_yards | 207.7 | 292.8 | 249.5 |
| passing_tds | 1.38 | 2.30 | 1.5 |
| rushing_yards | 21.6 | 56.5 | 29.5 |

The prop path priced `P(passing yards >= 249.5)` at 24.7%, so the board showed a
large under edge, while the fantasy tab implied a comfortable over.

## The cause

`predict()` shrank the GLM estimate toward the league mean:

```python
n = len(player_rows)        # same-season prior games ONLY
shrunk = prior_mean + (n / (n + k)) * (pred_mean - prior_mean)      # k = 2
```

`n` counted games played *in the current season*. At week 2 `n = 1`, so the
weight on the player-specific estimate was `1/3` and two thirds of the
projection was the league average. Allen's own trailing average was 288.0
passing yards, the league prior is 205.4, and the model returned 207.7.

There was also a discontinuity at the week 1/2 boundary. Week 1 has
`player_rows` empty, which routes to the cold-start branch that blends against
the player's *own* trailing average. That branch behaves well. Week 2 fell
through to the league-mean branch. The same player moved ~50% between the two
weeks with no new information:

| player | stat | trailing | wk1 | wk2 before | wk2 after |
|---|---|---|---|---|---|
| Bijan Robinson | rushing_yards | 96.8 | 89.3 | 44.6 | 65.1 |
| Amon-Ra St. Brown | receiving_yards | 82.0 | 135.3 | 69.2 | 116.2 |
| Ja'Marr Chase | receiving_yards | 56.5 | 73.5 | 40.7 | 52.8 |

## Why it landed entirely on the prop board

Shrinkage compresses predictions toward the middle, which under-projects the top
of the distribution. Kalshi only lists high-usage players, so the board is drawn
entirely from the quintile the model under-projects. Out-of-sample bias on the
top-form quintile, by week, 2025 holdout:

```
                        wk1-2    wk3-4    wk5-7   wk8-11  wk12-18
rb/rushing_yards       -33.7%   -20.9%   -13.6%   -16.7%    -8.1%
rb/carries             -34.3%   -14.5%    -2.9%    -4.6%    +0.7%
wr_te/receiving_yards  -30.7%    +0.3%    -5.7%    +4.6%    +4.2%
```

The fantasy board escaped it because its trailing anchor carries most of the
weight and the GLM only enters at `glm_blend_weight` (0.35).

## This is underfitting, not overfitting

Out-of-sample calibration slopes (regress actual on predicted; `>1` means
predictions are too compressed):

```
RB rushing_yards  1.245    RB carries       1.138    RB receiving_tds 1.530
QB passing_tds    1.163    QB carries       1.227    WR receiving_tds 1.230
```

Actuals vary more than predictions. The models were over-regularised, not
over-fit.

## The fix

The `n / (n + k)` ramp is gone. Each stat carries a constant weight:

```python
w = shrinkage_weight(model_name, stat)
shrunk = prior_mean + w * (glm_prediction - prior_mean)
```

Weights live in `models/shrinkage_weights.json`, regenerated by
`scripts/diag/fit_shrinkage_weights.py`.

### Why constant in `n`

Measuring the weight that actually minimises squared error, by least squares on
`(actual - prior) ~ w * (glm - prior)`, shows it is close to flat in `n`:

```
                        n=1    n=2-3   n=4-7    n=8+    the old ramp
wr_te/receiving_yards   0.73    0.70    0.76    0.71    0.33 -> 0.85
wr_te/receptions        0.83    0.82    0.85    0.79    0.33 -> 0.85
wr_te/targets           0.82    0.82    0.84    0.77    0.33 -> 0.85
rb/carries              0.72    0.87    0.84    0.85    0.33 -> 0.85
qb/passing_yards        0.91    0.80    0.85    0.70    0.33 -> 0.85
```

The GLM's rolling features already span season boundaries, so its evidence base
barely depends on how many games the current season has had. Ramping the weight
by same-season games shrinks against a quantity that is not the relevant sample
size. What genuinely varies is the stat: a target share is far more predictable
than a rushing touchdown.

### Why least squares rather than a grid search

An earlier attempt tuned `(alpha, c, k)` per stat against a hand-built
objective. It scored well but **18 of 22 stats had unstable parameters across
leave-one-season-out folds** -- it was fitting noise. The least-squares weight,
estimated on thousands of rows per stat, is stable:

```
19 of 22 stats have leave-one-season-out CV < 10%
21 of 22 < 25%
wr_te/targets 0.4%   wr_te/receiving_yards 0.7%   rb/carries 1.3%
```

`wr_te/rushing_tds` is the sole exception (CV 92%) and falls back to the median
weight, enforced by `_MAX_LOO_CV` in `models/shrinkage.py`.

### Results

Leave-one-season-out over 2018-2025 (339,830 walk-forward rows; for eval season
Y the models are fit on 2015..Y-1):

| | nMAE | slope err | \|topform\| | \|topform wk<=5\| |
|---|---|---|---|---|
| **all stats** | | | | |
| old `n/(n+2)` | 0.9503 | 0.4207 | 15.2% | 22.3% |
| per-stat weight | 0.9258 | 0.2987 | 12.3% | 14.7% |
| **prop-board stats** | | | | |
| old `n/(n+2)` | 0.7484 | 0.3807 | 14.4% | 20.7% |
| per-stat weight | 0.7192 | 0.1075 | 11.0% | 12.1% |

Calibration-slope error on the stats that populate the board falls 72%.

Residual bias on the top usage tier, per stat, is small:

```
qb/attempts -0.5%   qb/passing_yards -0.8%   qb/completions -1.8%
qb/passing_tds -2.9%   wr_te/targets -2.6%   rb/carries -3.5%
wr_te/receptions -3.8%   wr_te/receiving_yards -4.9%   rb/rushing_yards -5.4%
```

## Things that were tried and rejected

1. **Global constant `c = 4`** (`n_eff = n + 4`, keeping `k`). Shipped briefly,
   then superseded. Better than the old ramp but beaten by per-stat weights on
   every metric (prop nMAE 0.7352 vs 0.7192, slope err 0.2707 vs 0.1075).
2. **Per-stat grid search** over `(alpha, c, k)`. Unstable, see above.
3. **Trailing-form anchor** (`trailing + w*(glm - trailing)`). Won on 4 seasons,
   lost on 8. Better calibration slope over all stats but worse nMAE and worse
   early-season bias on the prop stats.
4. **Clamping the fitted weights** to `[0.3, 1.2]` or `[0.4, 1.1]`. Degraded
   every metric. The weights above 1 are doing real work; the output is bounded
   by the existing `ceiling` clip instead.
5. **Per usage tier weights**, `(stat x trailing-form tercile)`. Bought a hair of
   MSE (prop nMAE 0.5570 vs 0.5595 on the top tier) at the cost of *worse* bias
   on that tier (13.6% vs 10.6%). The fitted top-tier weights come out lower,
   i.e. it shrinks starters harder, which is the wrong direction for the board.
6. **A discrete boundary correction.** Hypothesised that Kalshi's "16+" markets
   settle on `X >= 16` while `prob_over` computes `P(X > 16)`, which would bias
   every count prop down. Checked: every strike Kalshi lists is a half-integer
   (`pct_half = 1.0` for all eight series), so `prob_over(15.5)` already gives
   `P(X >= 16)`. No bug.
7. **The fantasy context factors alone, without the trailing blend.** Moves the
   gap to market from -0.064 to -0.054 and makes mean absolute disagreement slightly
   worse. `_stat_multipliers` only covers fantasy *scoring* stats, so `attempts`,
   `completions` and `carries` receive no adjustment at all. The factors only pay
   off once the trailing blend comes with them -- see the second fix below.

## Second fix: the prop board now prices off the fantasy projection

The shrinkage fix removed the wall of unders but left the board at 72% unders
with a median edge of 0.226, and its wildest remaining edges sat on backups and
role-change players (Ray Davis, Drew Lock, MarShawn Lloyd) rather than stars.
That is a different defect: the prop path priced the raw GLM, which cannot see a
depth-chart change, while the fantasy path already handles it.

### What the data says about the split

Regressing out of sample, per stat, on walk-forward rows:

    (actual - prior) ~ a*(glm - prior) + b*(trailing - prior)

| stat | a (GLM) | b (trailing) | trailing share |
|---|---|---|---|
| rb/carries | 0.091 | 0.751 | 89.1% |
| wr_te/receptions | 0.139 | 0.660 | 82.6% |
| rb/receptions | 0.214 | 0.506 | 70.2% |
| wr_te/receiving_yards | 0.292 | 0.471 | 61.8% |
| qb/passing_yards | 0.301 | 0.468 | 60.9% |
| rb/rushing_yards | 0.372 | 0.480 | 56.4% |

A player's own trailing form earns 50-90% of the weight on most box-score stats.
The fantasy path gives it ~65% (`glm_blend_weight = 0.35`). **The prop path gave
it 0%.** The fantasy board was closer to right the whole time.

### The change

`evaluate_prop` now prices against `fantasy_service.prop_stat_projection`: the
same trailing blend, depth-chart role context and matchup factors the fantasy
board uses. A line `L` is priced as `distribution.prob_over(L / multiplier)`,
which is exact for any distribution family because `P(m*X > L) == P(X > L/m)`.

`predict()` is untouched, so the locked fantasy calibration stays valid. Stats
the fantasy pipeline does not model (`attempts`, `completions`, `carries` are
not fantasy scoring stats) keep the GLM distribution. Behind
`AppSettings.use_fantasy_projection_for_props`.

**The Kalshi market anchor is excluded.** Fitting a projection to a quote and
then grading edge against that same quote prices every market at no edge by
construction. This is why the two tabs still differ on Josh Allen -- fantasy
shows 292.8 passing yards because it folds in the market's own view, the prop
path shows an effective 248.4 against a 249.5 line. That difference is the point,
not a bug.

### Result, 2026 week 2 board vs Kalshi

| stat | market | GLM path | gap | fantasy path | gap |
|---|---|---|---|---|---|
| passing_yards | 0.501 | 0.462 | -0.039 | 0.495 | **-0.006** |
| passing_tds | 0.491 | 0.450 | -0.040 | 0.472 | **-0.019** |
| receiving_yards | 0.502 | 0.463 | -0.039 | 0.505 | **+0.003** |
| receptions | 0.509 | 0.409 | -0.100 | 0.480 | **-0.029** |
| rushing_yards | 0.495 | 0.417 | -0.078 | 0.486 | **-0.010** |

With `attempts`, `completions` and `carries` included:

| stat | market | GLM path | fantasy path |
|---|---|---|---|
| carries | 0.499 | 0.352 (-0.147) | 0.421 (**-0.078**) |
| attempts | 0.491 | 0.463 (-0.029) | 0.462 (-0.029) |
| completions | 0.497 | 0.465 (-0.032) | 0.466 (-0.031) |

```
overall gap    -0.066  ->  -0.018
mean |gap|      0.155  ->   0.097     (37% closer to market)
called UNDER    63.5%  ->   52.2%     (balanced)
```

`attempts` and `completions` barely move because the GLM and the trailing blend
already agree on them; they were never the problem (gap ~-0.03). `carries` is
halved but remains the worst stat on the board.

Josh Allen's passing-yards prop went from a 24.7% model probability against a
51.5% market (a large fake under edge) to 49.8%.


## What this does not fix

1. **QB passing yards.** The raw GLM returns ~211 for Allen against a trailing
   average of 288, so no shrinkage setting reaches the fantasy path's 292.8. The
   gap is in the GLM's own estimate. Its team and opponent rolling context
   features are built from one or two games in early season, well off the
   distribution they were trained on.
2. **`carries`** still has the largest gap to market (-0.078 after the fix, from
   -0.147). Whether that is genuine edge, thin week-2 liquidity or model bias is
   not decidable without outcomes.
3. **Residual disagreement with the 2026 week 2 market**, after the fix:

   ```
   stat              n    mkt    model     gap
   carries          24   0.494   0.336   -0.158
   receptions      112   0.509   0.409   -0.100
   rushing_yards    58   0.498   0.428   -0.070
   passing_yards    31   0.509   0.469   -0.040
   receiving_yards 121   0.501   0.465   -0.036
   ```

   Larger than the historical top-tier bias predicts. Could be genuine edge,
   thin week-2 liquidity, or a 2026 shift; week 2 outcomes are needed to tell.
   Do not trade the board on the assumption it is edge.

## A side effect worth knowing

`api/server.py` builds the app at import, which starts the fantasy-slate and
prop-board prewarm threads. The prop-board one holds a process-wide lock for as
long as it runs. That was harmless while it prewarmed week 1, which has no open
Kalshi markets and so finished instantly; pointing it at the live week made it a
real multi-minute build and any test touching the board started racing it.
`tests/conftest.py` now disables both prewarms, which is what should have been
happening all along -- a test run should not be doing Kalshi scans and model
fits on a background thread.
